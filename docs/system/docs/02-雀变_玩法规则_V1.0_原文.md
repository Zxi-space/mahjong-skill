# 雀变｜麻将电子技能系统 V1.0 玩法规则

> 文档状态：**V1.0 设计基线（待线下试玩验证）**  
> 产品名称：雀变（暂定，尚未进行商标、域名核查）  
> 核心定位：**线下实体麻将的电子技能卡牌工具**，不是线上麻将游戏、自动裁判或计分系统。  
> 版本日期：2026-10-19

---

## 00. 一页快速上手

**你需要：** 一桌线下麻将、建议 4 位玩家、至少 1 台可以访问网页的手机。

**经典卡盒（单机）**
1. 打开「雀变」→「经典卡盒」，选一套牌库。
2. 选择人数，系统打乱电子牌库；按玩家依次抽出两张技能牌。
3. 现实中照常打麻将；技能是否能用，以卡面写明的使用时机和本桌约定为准。
4. 发动时亮出电子卡，线下执行效果；点「已使用／放弃」，需要时手动撤销误触。
5. 一局麻将结束，点击「下一局」，全部归档旧卡、重新抽牌。

**好友牌桌（4 人联网）**
1. 房主创建房间并选择牌库，其他人扫码或输房间码加入。
2. 4 人就位并共同确认规则，房主开始本局；每人手机获得自己的 2 张卡。
3. 玩家点击卡牌→查看完整规则→选择合法目标→发起使用；涉及实体操作时由在场玩家完成并确认。
4. 若技能可以防御，目标玩家选择「使用防御」或「放弃响应」，然后继续结算。
5. 系统记录技能消耗和电子状态，但**不检测线下摸、吃、碰、杠、胡的合法性**。

**核心原则：** 麻将照常打，卡牌只是增加一层娱乐互动。任何无法安全、明确执行的技能，本桌都可以事先禁用。

## 01. 产品定位与玩法边界

### 1.1 要做什么
- 用电子卡牌替代需要购买、打印和携带的实体技能牌。
- 提供抽卡、洗牌、私有手牌、使用与弃牌、效果说明、牌局同步、基础日志。
- 允许用户从**官方预设效果模板**创建新卡，并组装个人牌库。
- 支持「一台手机轮流使用」和「四人各自手机扫码加入」两种模式。

### 1.2 明确不做什么（V1.0）
- 不构建线上麻将棋盘、不识别麻将牌图像、不追踪整副麻将墙。
- 不做自动和牌判断、番型计算、真实货币结算或下注功能。
- 不做卡牌数值成长、付费抽卡、攻击力／血量、复杂技能连锁。
- 不允许用户注入脚本或任意代码作为卡牌效果。

### 1.3 优先级规则
1. **安全、公平、线下全员事先同意**优先于任何技能。
2. 本桌麻将的基本规则优先于卡牌；唯一例外是开局明确启用的「进阶实体操作牌」，且仅在卡面明确范围内修改摸牌／换牌动作。
3. 游戏模式与牌库设置优先于单张卡的普通说明；如果发生矛盾，视为争议并暂停卡牌结算。
4. 平台只管理电子状态；线下执行的正确性以在场玩家共同确认为准。

### 1.4 麻将地方玩法兼容
- V1.0 不限定国标、四川、广东、台湾或其他地方玩法；由玩家自行选择本桌麻将规则。
- 如果基础玩法存在定缺、换三张、立直锁手、花牌、特殊杠牌／补牌等限制，**与之冲突的实体技能必须关闭**。
- 系统只提供提示标签：`通用`、`需协商`、`进阶实体操作`；不宣称对任何地方规则自动兼容。
- 不使用实体牌操作能力的卡，普遍更容易跨地方麻将规则使用。

## 02. 基础术语

| 术语 | 定义 |
|---|---|
| 一场 | 玩家从建房到主动结束的聚会；可包含多局麻将。 |
| 一局 | 从现实麻将发牌开始，到按本桌规则出现胡牌、流局等结束状态；不是每出一张牌的「回合」。 |
| 牌库 | 这局可抽取的电子技能卡集合；每张卡有稳定 ID 与版本。 |
| 技能手牌 | 当前分配给玩家、尚未弃置的电子技能卡，和实体麻将暗牌不同。 |
| 行动技能 | 由玩家主动点选发动的电子卡牌效果。 |
| 响应技能 | 其他人向自己发动技能时，可选择发动的防御效果。 |
| 被动技能 | 满足卡面条件时，玩家手动确认结算的效果。 |
| 娱乐星 | 仅供当场趣味展示的非货币虚拟记录，不等同麻将计分或现实财物。 |
| 房主／主持人 | 创建房间、启动新局、处理异常电子状态的人；**不是实体麻将的权威裁判**。 |

## 03. 两种产品模式

### 3.1 经典卡盒：单机工具

- 推荐人数：2～4 人；默认展示 4 个位置，支持按实际人数选择。
- 使用方式：一台手机在桌边轮流看卡／抽卡；可以无账号使用，初版允许本机保存。
- 电子发牌：默认每位玩家 **2 张**，顺次分配；每人通过「按住查看」临时查看自己的牌，松开遮盖，避免旁观偷看。
- 卡牌使用、弃牌、误触撤销均为**手动工具操作**；不会要求其他人必须在线确认。
- 隐私限制：一台设备无法对旁边玩家提供强隐私保证；需由桌上玩家遵守传机与不窥视约定。
- 断网体验：已下载资源可以在本地继续管理；是否支持完整离线安装由后续 PWA 版本决定，V1.0 不强制承诺。

### 3.2 好友牌桌：四人联机

- 固定 4 人和东／南／西／北四个席位；首版不支持围观者插入抽卡。
- 创建房间无需注册；使用房间码＋一次性会话令牌加入。登录、跨设备找回为以后迭代。
- 房主设定牌库、每局卡牌规则，其他 3 人进入前可查看设定；全员就绪才能开始。
- 房间中：私有技能仅本人可见；公开发动事件和已公开效果全员可见。
- 网络异常：恢复后同步服务端快照与事件日志；未解决的技能停留在待确认状态，不能悄悄视为成功。
- 离线玩家：短暂掉线可重连；不能重连时，房主经桌上玩家同意选择「手动裁定／终止该次技能」。

### 3.3 模式对比

| 能力 | 经典卡盒 | 好友牌桌 |
|---|---|---|
| 洗牌与发牌 | 本机完成 | 服务端统一完成 |
| 个人技能隐私 | 轮流遮盖查看 | 仅本人账号会话可见 |
| 目标选择 | 手动记录 | 房间内选择其他席位 |
| 防御响应 | 口头协调，手动标记 | 对应玩家在手机上响应 |
| 状态与历史 | 本机保存 | 服务端保存并同步 |
| 争议处理 | 玩家手动回退 | 房主发起、全员线下认可后裁定 |

## 04. V1.0 标准局规则

> 这一章定义**默认推荐规则**。经典卡盒可切换到「纯工具自由使用」，不强制执行自动次数校验。

### 4.1 开始一局
1. 确认麻将地方玩法和是否启用进阶实体操作牌。
2. 将本局选定牌库洗匀，**每个牌库实例在单局内不重复抽同一张卡**，除非该牌库作者明确设置了副本数量。
3. 每位玩家发两张技能：推荐牌组采用**一张行动／干扰类牌 + 一张防御／增益／特殊类牌**，避免同时发两张毫无使用时机的牌。
4. 增益型被动牌可按卡面要求开局公开；其他未发动技能保持私有。
5. 玩家线下发牌结束后，房主点「开始本局」，正式进入可发动状态。

### 4.2 默认使用次数
- 每名玩家**每局最多主动发动 1 张**行动／干扰／主动特殊牌。
- 每名玩家**每局最多使用 1 张防御响应牌**；防御不占主动使用次数。
- 被动牌在指定条件出现时，由持有人申请并由相关玩家口头确认；默认**每张只结算 1 次**，不消耗主动或响应次数。
- 同一电子技能卡**只能结算一次**；结算后进入弃牌区，不回到手牌。
- 技能手牌最多 **3 张**；超限抽卡效果要求立即自行选择弃掉多余的未使用技能。
- 一局结束，未使用技能统一弃置，**默认不跨局继承**。

### 4.3 默认发动时机

| 时机代号 | 中文解释 | 可否主动技能 |
|---|---|---|
| `BEFORE_HAND` | 发牌完毕、正式开始出牌前 | 卡面注明才允许 |
| `OWN_TURN_BEFORE_DISCARD` | 轮到自己且已完成必要摸牌、尚未打出弃牌 | 允许卡面限定的主动技能 |
| `ON_TARGETED` | 自己成为技能目标、技能未结算时 | 允许合法防御响应 |
| `ON_DECLARED_EVENT` | 玩家口头宣告碰、杠、胡等事件 | 仅触发对应被动，不自动判合法性 |
| `AFTER_HAND` | 一局结束后的回顾环节 | 仅允许结算型被动 |

**禁区：** 自己或其他玩家正在判断抢胡、吃、碰、杠、补花等本桌优先级动作时，不得插入实体牌交换或摸牌改动。麻将胡牌成立后的裁定不会因技能被撤回。

### 4.4 牌库抽取与耗尽
- 牌库抽取采用随机洗牌后的顺序抽取；多人模式由服务端生成并持久化顺序／随机种子，客户端不能决定抽卡结果。
- 如果因额外抽卡导致牌库耗尽，此抽卡步骤**跳过，不洗回已经使用的牌**。
- 需要全员同时抽卡的技能，如牌库余量不足所有目标人数，则技能**不可发动、不消耗使用次数**。
- 每局开始重新洗牌；同一牌在不同局再次抽到是正常的。

### 4.5 现场执行、弃牌与撤销
- **电子效果**：平台自动更新抽卡、技能交换、公开标记、娱乐星等电子状态。
- **实体效果**：平台弹出规则步骤，等待相关玩家现实中执行，然后发起者和被影响玩家确认；房主可以处理无法确认的异常。
- 在涉及实体牌操作之前，先确认没有冲突的麻将动作；交换牌时只处理未公开暗牌。
- 误触撤销仅在技能**尚未执行实体效果且尚未向其他玩家揭示不可恢复的信息**时允许；已查看暗牌、已执行换牌等不可逆效果，不提供无条件撤销。

## 05. 完整技能结算流程

### 5.1 主动技能
`检查可用性 → 选择目标 → 公示将发动 → 目标响应（如需） → 结算电子/实体效果 → 确认完成 → 消耗次数并记录`

1. 发起者点击技能，服务端校验：房间、局状态、卡牌归属、使用时机、次数、合法目标、牌库设置。
2. 需要目标的技能先由目标选择「防御／放弃响应」。**默认不设置自动超时放弃**，以免手机锁屏导致被误判。
3. 只允许**一次防御响应，不允许防御反制防御、无限反弹、额外嵌套技能**。
4. 防御成功：按防御卡说明取消或改向原技能；两个效果各自进入明确状态并留下事件。
5. 需要现实操作：相关玩家现场执行，并在手机端确认已完成；与事实不一致则进入争议流程。
6. 不可逆电子信息（查看手牌、随机选卡）一旦已被展示，不能把操作当作从未发生。
7. 所有技能操作带唯一 `action_id`，避免重复点击造成二次结算。

### 5.2 被动技能
`玩家口头宣布实际事件 → 持牌人点击触发 → 人工确认 → 记录娱乐星或其他效果`

- 无摄像头、无牌面识别；服务端只验证电子使用频率与卡牌状态。
- 奖励仅用于娱乐星，**不得自动映射现金输赢或本地麻将番数**。

### 5.3 状态机（联网）

| 状态 | 含义 | 后续 |
|---|---|---|
| `AVAILABLE` | 未使用 | 可发起 |
| `PENDING_RESPONSE` | 等待防御或放弃 | 继续或取消 |
| `PENDING_MANUAL` | 等待现场动作完成 | 确认、争议 |
| `RESOLVED` | 技能结算成功 | 归档到已使用 |
| `COUNTERED` | 被防御抵消 | 归档，原技能是否消耗由卡面设定（默认消耗） |
| `VOIDED` | 校验前发现不合法／全员裁定作废 | 未发生效果可原路恢复 |
| `DISPUTED` | 玩家不同意线下执行结果 | 暂停其他技能，等待裁定 |

### 5.4 冲突和争议
- 同一时间只结算**一项技能**；其他尝试排队或提示稍后。
- 胡牌、抢杠等已进入现实麻将裁定时，暂停新技能请求。
- 服务端只负责电子记录的事实一致性，**不作为实体麻将合法性的最终裁判**。
- 争议发生时，房主记录玩家共识：完成／作废／保留现状继续；推荐四名玩家线下口头同意。
- 对结果不同意时，房主可终止本次技能，但不能擅自恢复已经泄露的私密信息。
- 某张卡反复造成争议，可从下一局牌库移除；当前局不得偷换卡面定义。

## 06. 官方基础卡池：24 张原创概念牌

> `默认`：轻松局可启用。`进阶`：需要额外线下共识，默认关闭。  
> 为避免地域麻将差异，基础牌库主要影响电子技能和娱乐星；涉及换摸实体麻将的仅作**显式选配**。  
> 以下卡名及机制是本项目的原创提案，**尚未完成试玩和平衡性验证**。

### 6.1 行动类（8 张）

| ID | 技能 | 效果与使用时机 | 限制 | 默认 |
|---|---|---|---|---|
| A01 | 眯一眼 | 自己出牌前，请目标将暗牌背面洗匀，随机抽一张仅给自己查看后放回。 | 不得在抢胡／碰杠响应中发动；信息不可撤销。 | 是 |
| A02 | 牌墙侦探 | 自己出牌前，私下查看牌墙最上方一张麻将牌并放回原位置，不改变次序。 | 不允许翻看其他牌，现场执行需共同认可。 | 进阶 |
| A03 | 换手气 | 自己刚完成常规摸牌、尚未弃牌时，将刚摸的牌放回约定的牌墙底部，再摸最上方一张。 | 仅限明确允许改动牌墙的地方玩法；不在补花／杠后补牌时使用。 | 进阶 |
| A04 | 移花接木 | 自己出牌前，与目标玩家各从暗牌中背面选一张，双方同时交换。 | 不交换公开面子／花牌；双方暗牌张数各保持不变。 | 进阶 |
| A05 | 小小交换站 | 自己出牌前，与目标玩家各选一张未使用的**电子技能卡**并交换。 | 系统确认双方都有可交换的技能，交换原子完成。 | 是 |
| A06 | 技能补给包 | 自己出牌前，从技能牌库抽 1 张电子卡；手牌若超 3 张，立即弃掉多余技能。 | 若牌库耗尽则不可用；本次发动已消耗主动机会。 | 是 |
| A07 | 公开奖开奖 | 自己出牌前，目标玩家自行选择一张实体暗牌，向全场亮出后立即收回。 | 不可指定已经公开的牌；不改变归属。 | 是 |
| A08 | 偷偷瞄卡盒 | 自己出牌前，随机查看目标玩家一张**尚未公开的电子技能卡**。 | 仅发动者可见，查看动作不可撤销。 | 是 |

### 6.2 防御类（5 张）

| ID | 技能 | 效果 | 响应条件 |
|---|---|---|---|
| D01 | 金钟罩 | 抵消一次以自己为目标的敌对技能。 | 被指定且对方尚未结算；不抵消全场事件。 |
| D02 | 照妖镜 | 抵消针对自己的实体暗牌查看，然后由发动者向自己展示一张自选暗牌。 | 仅回应 `A01` 一类查看暗牌技能；无二次响应。 |
| D03 | 不换不换 | 抵消一次要求自己交换实体麻将暗牌的技能。 | 仅回应实体换牌技能。 |
| D04 | 拒绝封印 | 解除当前正要施加给自己的电子技能使用限制。 | 仅回应 `I01/I03` 一类控制电子技能的技能。 |
| D05 | 弹弹镜 | 将一次单目标**电子技能效果**转移给原发动者；若原发动者不是合法目标则直接抵消。 | 仅回应可转移的指定电子技能；只结算一次，不继续反弹。 |

### 6.3 增益类（5 张，被动条件牌）

| ID | 技能 | 触发条件 | 娱乐奖励 |
|---|---|---|---|
| B01 | 碰碰好运 | 本局第一次完成本桌认可的合法碰牌后手动申请 | +1 娱乐星 |
| B02 | 杠杠有礼 | 本局第一次完成本桌认可的合法杠牌后手动申请 | +1 娱乐星 |
| B03 | 胡啦胡啦 | 本局自己按本桌规则合法胡牌后手动申请 | +2 娱乐星 |
| B04 | 慢慢来嘛 | 本局结束时，自己至少还留有一张未使用电子技能牌 | +1 娱乐星 |
| B05 | 防住啦 | 本局成功用防御技能抵消或改向一次效果后手动申请 | +1 娱乐星 |

> 被动牌不会改变麻将计分。只有玩家确认条件成立才记录娱乐星；每张被动卡每局最多触发一次。未启用「娱乐星」的房间可以关闭 B 类牌。

### 6.4 干扰类（3 张）

| ID | 技能 | 效果 | 边界 |
|---|---|---|---|
| I01 | 小声一点 | 指定玩家直到其下一次完成弃牌前，不得**主动发动电子技能**。 | 不阻止摸、吃、碰、杠、胡，也不阻止防御响应。 |
| I02 | 卡盒透明化 | 指定玩家公开一张自选的未使用电子技能卡，公开状态持续到本局结束或该卡被弃置。 | 不揭露实体麻将暗牌。 |
| I03 | 补给暂停 | 指定玩家本局内不能通过其他技能获得额外电子技能卡。 | 不删除已持有卡，不影响下一局。 |

### 6.5 特殊类（3 张）

| ID | 技能 | 效果 | 发动限制 |
|---|---|---|---|
| S01 | 全员开盲盒 | 四名玩家各从当前电子牌库抽一张技能；抽后超手牌上限的玩家立刻弃到 3 张。 | 必须有至少 4 张剩余牌；按席位顺序发牌，整体一次完成。 |
| S02 | 命运小骰子 | 服务端随机生成 0、1 或 2 枚娱乐星，加入本人本场娱乐星。 | 仅作娱乐展示，不换算真实输赢。 |
| S03 | 友情漂流瓶 | 四人各选择一张未使用电子技能，以东→南→西→北→东的顺序同时传递。 | 四人都必须有可传递的卡；统一提交后一起交换。 |

### 6.6 推荐牌库预设

**轻松入门牌库（16 张）：** `A01,A05,A06,A07,A08,D01,D02,D04,D05,B01,B02,B03,B04,B05,I02,S02`。不包含改变实体牌墙、实体换牌、较复杂的全员同步事件。  
**完整欢乐牌库（24 张）：** 上表全部 24 张；标为「进阶」的 A02/A03/A04 只有在房间设置中由全体玩家确认后才启用。  
**纯电子卡盒：** 只使用不需要改变实体牌状态的卡牌；用户可以自行建立牌库，支持自由手动执行。

> 研发时需要增加卡牌「可用目标集合」「需要线下执行」「是否允许防御」「是否公开」「需要牌库剩余张数」等机器可读字段。对默认轻松牌库，如果设置的配牌类别导致库存不足，前端必须提示并禁止开局，不能静默重复发牌。

## 07. 自定义卡牌：预设效果模板

### 7.1 创作自由与执行边界

玩家可以配置：
- 卡牌名称、简短描述、封面主题、装饰边框、牌组归属。
- 官方白名单内的效果模板，以及模板允许的有限参数：目标范围、使用时机、每局次数、可选奖励数量。
- 是否放入个人牌库、是否允许共享、牌库封面和标签。

玩家**不能**：
- 自行编辑任意 JavaScript／Python 逻辑并要求系统执行。
- 自由填写任何「禁胡」「强制付款」「加倍真钱」之类的效果而让系统自动判定。
- 绕过模板规则自行创建不受限的随机摸牌、无限响应或跨局隐式效果。
- 通过自定义卡片修改服务端的房间权限、玩家隐私和他人账户信息。

### 7.2 V1.0 模板清单（首版建议）

| 模板代码 | 模板 | 主要参数 | 执行者 |
|---|---|---|---|
| `PEEK_TILE` | 查看实体暗牌 | 指定目标、查看张数（固定 1） | 线下人工 |
| `REVEAL_TILE` | 展示实体暗牌 | 指定目标、公开范围 | 线下人工 |
| `PEEK_WALL_TOP` | 查看牌墙顶部 | 是否在本桌启用进阶操作 | 线下人工 |
| `REPLACE_DRAWN_TILE` | 替换刚摸的牌 | 固定重新摸 1 张 | 线下人工 |
| `SWAP_CONCEALED_TILE` | 玩家交换暗牌 | 指定目标、交换数量（固定 1） | 线下人工 |
| `DRAW_SKILL` | 抽电子技能 | 抽取张数（初版固定 1） | 服务端 |
| `PEEK_SKILL` | 查看电子技能 | 指定目标、数量（固定 1） | 服务端 |
| `SWAP_SKILL` | 交换电子技能 | 指定目标、数量（固定 1） | 服务端 |
| `CANCEL_TARGET_SKILL` | 防御抵消 | 可防御的效果类型 | 服务端＋人工 |
| `LOCK_SKILL_ACTION` | 暂时禁用电子技能 | 指定目标、持续到下次弃牌或本局结束 | 服务端＋人工 |
| `REVEAL_SKILL` | 公开电子技能 | 指定目标、持续时限 | 服务端 |
| `EVENT_STAR_REWARD` | 条件娱乐星奖励 | 事件类型（碰／杠／胡／局末等）、1～2 星 | 人工确认＋服务端 |
| `RANDOM_STAR_REWARD` | 随机娱乐星 | 候选值（0/1/2） | 服务端 |
| `MASS_SKILL_DRAW` | 全场电子抽卡 | 对象固定全场；库存前置检查 | 服务端 |
| `PASS_SKILL_CIRCLE` | 全场顺位传电子技能 | 固定传 1 张；全员完整确认 | 服务端 |

> 模板参数依赖**模板自身约束**：例如「碰牌后奖励」不能改为「任意时机」，「查看自己暗牌」不构成有效技能，防御模板不能由非目标玩家随意触发。

### 7.3 编辑体验
1. 选择卡牌模板（按「行动／防御／增益／干扰／特殊」分类）。
2. 填卡牌名称与一句话说明；详细规则由模板生成，必要的固定警告不可删除。
3. 选择目标、次数等**该模板允许**的参数；非法组合选项自动隐藏。
4. 右侧实时预览带可爱麻将元素的卡面。
5. 保存草稿→系统校验→加入自己的牌库→可选分享链接。
6. 编辑已发布卡牌时创建**新版本**，当前正在使用的房间继续使用开局冻结的旧版本。

### 7.4 数据结构示例

```json
{
  "card_id": "A04",
  "version": 1,
  "name": "移花接木",
  "category": "ACTION",
  "template_code": "SWAP_CONCEALED_TILE",
  "trigger": "OWN_TURN_BEFORE_DISCARD",
  "target_type": "ONE_OTHER_PLAYER",
  "manual_execution": true,
  "requires_target_ack": true,
  "advanced_physical_operation": true,
  "max_uses_per_hand": 1,
  "parameters": { "quantity": 1 }
}
```

实现备注：这只是一张卡牌定义，不是可执行代码；后端必须使用安全的模板调度表，把 `template_code` 映射到经过验证的处理器。

## 08. 房间、权限与同步

### 8.1 房间角色
- 房主：创建房间、设置牌库、邀请玩家、开启／结束一局、发起异常裁定。
- 玩家：查看私有卡、发动自己持有卡、响应指向自己的技能、查看公开日志。
- 所有人：开局前查看规则设定；现实中协商是否启用进阶牌。
- 默认不提供旁观者查看私有技能的功能。

### 8.2 房间流程
`WAITING（等待加入） → READY（全员就绪） → DEALING（发牌） → PLAYING（进行中） → SETTLING（局末归档） → PLAYING（下一局） / CLOSED（房间结束）`

只有 `PLAYING` 可接受可发动技能；所有状态转换由服务端进行校验，并记录事件。

### 8.3 同步安全要求
- 服务端为电子技能状态唯一可信来源；客户端只能提交意图，不可自行决定抽卡和随机结果。
- 不发送其他玩家的私有技能正文和抽取顺序给未授权客户端；公开卡再广播。
- 单技能结算事务保证只消耗一次；强制带 `action_id` 幂等键。
- 需要人工确认的技能冻结本次所需的模板参数和目标，避免中途编辑牌库影响结算。
- 断线恢复以最新快照＋事件序号进行；禁止因重放重复执行抽卡或娱乐星奖励。
- 对房间码和会话令牌设置有效期；支持踢除掉线会话，避免匿名用户冒名进入。

## 09. 特殊场景与裁定实例

| 场景 | V1.0 标准处理 |
|---|---|
| 被人指定时没有防御牌 | 点「放弃响应」，原技能继续。 |
| 防御卡正在结算，另一人又点技能 | 提示「有技能正在结算」，后一个不受理。 |
| 胡牌已经成立，对方随后想禁胡 | 本版本不支持禁胡或撤销合法胡牌。 |
| 某地方麻将禁止额外摸牌或换牌 | A02/A03/A04 等冲突牌关闭；不能强制执行。 |
| 牌墙已不足，A03 想重新摸 | 不允许发动；不消耗使用次数。 |
| 全员抽卡但牌库只剩 3 张 | S01 不允许发动。 |
| 玩家技能手牌已达到 3 张 | 抽到新卡后必须立即弃至 3 张；未弃完不得继续技能。 |
| 目标拒绝完成实体换牌 | 技能进入争议，交由桌上玩家协商作废或更换卡牌规则。 |
| 技能已透露隐藏信息后想撤销 | 不提供无痕撤销；可作废效果但记录不可逆信息已披露。 |
| 两位玩家同时发动不同技能 | 以服务器首先获得锁的行动进入结算，其余拒绝或排队。 |
| 网络短暂断开 | 恢复快照；未确认实体动作继续显示「待确认」。 |
| 房主离开 | 房间可暂停并按桌上共识交接主持；不能静默销毁正在进行的局。 |
| 被动技能触发条件被争议 | 不自动奖励，待本桌确认后再手动记星。 |

## 10. 玩法平衡与可用性指标

**第一批测试建议：** 3～5 桌完整真实牌局，每桌 4 人；至少覆盖轻松牌库和含进阶牌的测试局。

观察项：
1. 首次进入：4 人扫码完成建房的成功率、时间和卡牌规则理解成本。
2. 平均每局操作手机次数：若明显影响出牌节奏，减少确认步骤与持续技能。
3. 单局技能争议次数：目标 **≤1 次／局**（设计目标，不是现有实测）。
4. 不可发动技能占比：因为玩法不兼容或剩余牌不足而不能使用的比例。
5. 玩家反馈：最有趣的卡、最拖沓的卡、最难理解的卡、是否愿意再次使用。
6. 手机误触、锁屏、断线重连、多人同时点击的恢复表现。

建议每次试玩完成后记录三类卡：**保留、重做、移除**。首轮不急于扩大到 100 张卡。

## 12. 品牌与视觉设计约束

**品牌关键词：** 可爱、轻松、麻将辨识度、亲切、社交、潮玩贴纸。  
**吉祥物：** 雀宝，以圆角「红中」麻将牌为核心原型；后续可发展「发财」「白板」同伴。  
**建议标语：** 「麻将照打，花样加倍！」

| 语义 | 颜色 | 推荐色值 |
|---|---|---|
| 主背景｜奶油白 | Cream | `#FFF6E9` |
| 主品牌｜麻将绿 | Mahjong Green | `#27866E` |
| 强调｜桃子红 | Peach | `#F18A7D` |
| 点缀｜布丁黄 | Pudding | `#FFD875` |
| 正文｜深松绿 | Pine | `#344A3F` |

**设计约束：** 高辨识度的麻将牌外轮廓、圆润立体卡片、轻微纸感和软阴影；按钮和文案对比度优先；卡面类别除了颜色还要有图标与文字，避免仅依赖颜色辨认。移动端优先，保证「抽牌」「查看」「发动」「确认」等高频操作一步可达。

## 13. 待试玩确认的关键决策

1. 本机经典卡盒是否默认严格限制每局一次主动使用，或首次直接提供完全自由工具模式？**当前建议：自由工具优先，标准限制可开启。**
2. 涉及实体牌墙变更／暗牌交换的 A02/A03/A04 是否进入默认产品？**当前建议：只作为明确勾选后的进阶扩展。**
3. 是否默认启用娱乐星？**当前建议：趣味可选，绝不连接真实输赢。**
4. 额外抽卡和牌库容量规则是否需要更简单？**当前建议：先保证总容量检查与手牌 3 张上限。**
5. 经典卡盒里 4 人同用一台手机时，私密查看是否足够方便？**需要拿真实手机在桌边验证。**

V1.0 是独立原创的**产品规则设计稿**，不是现行地方麻将官方规则，也不是对其他同类卡牌的复刻。所有涉及麻将牌墙、暗牌和动作优先级的技能，必须在实际牌桌环境中验证；卡面文字、名称、类别和玩法平衡在试玩后可能调整。为避免侵权，后续公开卡库应使用原创插画与卡面说明，不直接搬运第三方实体卡牌的美术或文字。
