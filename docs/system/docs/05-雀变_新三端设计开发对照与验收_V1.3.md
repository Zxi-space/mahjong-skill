## 二、已批准样式约束

- **线描**：深绿清爽轮廓、奶油白底、自然小线条、淡绿植物、淡青云、暖橙小点缀；没有厚重金边、水晶/塑料高光、写实茶室海报背景。
- **IP**：雀叽七角色（红中、发财、白板、东、南、西、北）以麻将牌而非鸟/鸡造型出现；每位牌面符号可读。禁止嘴喙、羽翼、羽毛、鸡冠；角色表情、手脚可以保留。
- **卡牌**：一张卡拆成画芯/卡框/纸张与动态规则文案/状态；PNG/WebP 用于独立画芯、可覆盖透明卡框，SVG 用于线性图标等；必须按“工程使用”单独出图，而不是整张卡的截图。
- **组件**：可读文本、动态数据和权限状态由真实 Taro/React/Next 组件承担；禁止以整页设计图替代可点 UI。
- **双主题**：三端 Light/Dark/跟随系统仍是要求；新批准的是 Light 图，Dark 尚需出新同构图稿，不许声称新 Dark 已通过视觉验收。

## 三、Client 功能边界矩阵

| 界面 | 必须有 | 必须没有 |
|---|---|---|
| 首页 | 抽电子技能入口、加入技能房间、卡库/卡盒、精简引导 | “一键打麻将”“自动出牌”等线上麻将操作 |
| 技能卡库 | 官方牌名与类型、分类搜索、卡片/详情真实规则 | 把插画示例名当作官方 24 卡定义 |
| 技能详情 | 技能时机、目标、次数、限制、状态、使用/加入卡盒 | 伪造现实麻将合法性判定 |
| 技能房间 | 房间号、四人状态、本人持有的电子技能卡、技能发动/响应、活动流 | 任何实体麻将手牌、牌河/牌墙、线上麻将牌桌/摸牌/出牌/碰杠胡/计分 |
| 个人中心 | 卡盒/记录/帮助/设置、游客可用项 | P0 阶段强制登录、付费会员入口，或把尚未实施的 P1 假装上线 |

注：“本局/第 N 局”只表示为线下这一局配套的**电子技能卡周期**；真实局由现场玩家线下开始与结束，系统不获取实体麻将牌的实时状态。

## 四、Portal 公开宣传验收

- Hero 用户一眼能读到“线下麻将的电子技能牌辅助工具”；不称“线上对战平台”。
- 动态规则：展示 24 张原始规则定义的真实技能，不采用生成图错字；精选卡插画单独可维护。
- 品牌角色：7 人身份可辨识，允许首页突出三位主角色，不能用小鸡替代。
- 各 CTA 真正进入小程序/H5/玩法指南，未发布的功能不要虚构下载/付费入口。
- 390/1024/1440 viewport 中标题可读、CTA 在合理位置、卡片可滑动或自然换行。

## 五、Admin 交互验收

- 4 KPI、7 日曲线、近期房间、待审卡牌、热门卡、技能列表都来自 API 或明确标注 Demo 数据；不默默显示设计稿的数字。
- 列表：搜索/筛选/分页、空表/加载/失败/无权限、操作危险确认；分类与官方技能版本一致。
- 审核：仅在真实审批流程存在且权限允许时显示，通过/拒绝有审计记录和拒绝原因；不能公开私牌正文。
- 当前仓库路由/组件按业务正式名称，不使用 Phase 编号命名。
- 1366/1440 适配无横向溢出，长表格可滚动，图表需配 Tooltip/Legend 和空态。

## 六、发布前 Gate

1. 视觉：3 张新稿对位；品牌角色无动物化；动态字体均是真实文字。
2. 业务：经典卡盒和四人技能房间可真实走完；独立技能权限、幂等与断网恢复达标。
3. 术语：未公开的卡称“我的技能卡”，不在 UI 出现“我的麻将手牌”。
4. 安全：没有在线摸牌/出牌/计分按钮；没有泄漏他人私有技能；无客户端决定随机结果。
5. 主题：Light 已按新稿对照，Dark 同布局可读且经独立验收；切换不刷新局状态。
6. 阶段：Phase 01～11 为 P0 发布链路；用户创作器按原规划属于 P1，社区/商业化属于 P2。

**验收标记**：每项记录 `待开发 / 已实现待验证 / 已实机验收 / 不适用`；这份文档更新不代表任何软件功能已完成。
